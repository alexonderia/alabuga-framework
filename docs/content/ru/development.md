# Разработка Framework

## Среда и команды

Node.js 24.19.0 и npm 11.17.0 закреплены в конфигурациях. npm ci устанавливает самостоятельный lock-файл. Репозиторий Constructor для сборки не нужен.

| Команда | Назначение |
| --- | --- |
| npm run tokens / check:tokens | Генерация слоёв и проверка дрейфа/ссылок |
| npm run build | ESM, IIFE, CSS, типы, материалы и проверка типов |
| npm test | Схемы, API, ресурсы и токены |
| npm run test:package | Проверка фактического npm-архива и exports |
| npm run test:consumers | Чистые Node, NodeNext и React-потребители |
| npm run build:docs / check:docs | Справочник, RU/EN, ссылки и ресурсы |
| npm run check:design | Целостность локальных источников Figma и реестра компонентов |
| npm run prepare:release | Локальный кандидат после проверок, без публикации |
| npm run test:browser | Состояния CSS, runtime, примеры и снимки |

## Оформление документации

Живой справочник и RU/EN-руководства используют готовый `standalone.css`: Alabuga Sans, компонентную типографику, кнопки, поле поиска и карточки. Общая оболочка находится в `docs/app/site.css`; цвета, отступы и скругления берутся из `--af-*`. Стили оболочки не переопределяют состояния компонентов в живых примерах.

`scripts/build-docs.ts` подключает тот же CSS фреймворка и копирует стили оболочки во все руководства. После изменения оформления выполните `npm run build:docs` и `npm run check:docs`; проверьте справочник, обе локализации и узкий экран. Оглавление руководств формируется из заголовков разделов при сборке.

Боковое меню объединяет темы по назначению: подключение, цвета и сетка, компоненты, документы, Constructor и API. Пункты используют ссылки с классами `af-btn af-btn--clear` (Clean, без постоянной обводки); текущая страница получает основную кнопку `af-btn` и `aria-current="page"`. Группы имеют заголовки и разделители, а на узком экране прокручиваются горизонтально. В RU/EN-руководствах отдельно сгруппированы установка и компоненты, API и форматы, разработка и выпуск.

Пример рабочей панели использует общие стили `demos/panel.css` в справочнике и на `/demos/panel.html`. У карточек и их содержимого `min-height: auto`: это позволяет WebKit пересчитывать высоту после переноса текста при изменении ширины. Проверка охватывает сужение и расширение панели, длинный комментарий и отсутствие вложенной прокрутки.

В разделе «Изменения и решения» группируйте подробные описания по версиям, от новых к старым. Сохраняйте сведения о возможностях, исправлениях, размерах, состояниях, совместимости и проверках выпуска; связанные решения и пояснения относите к соответствующей версии, без отдельных служебных разделов. Не сокращайте историю до общих тезисов. Данные журнала находятся в `docs/app/release-history.ts`; планы дальнейшей работы остаются за пределами журнала версий.

## Дизайн-токены и исходные материалы

design/figma-tokens.json — исходный snapshot. design/token-layers.json сохраняет эффективное сопоставление и явные поправки доступности. Генератор выпускает core/semantic/component CSS; существующие имена --af-* и вычисленные значения совместимы. Изменяйте исходные значения и генерируемые слои вместе; проверяйте контраст и визуальные эталоны.

Готовые WOFF2 находятся в src/fonts, TTC — в fonts. PDF/PPTX и ссылка Figma — в docs/brand-sources. Для регенерации нужны git lfs pull, Python и python -m pip install -r scripts/requirements-assets.txt; затем scripts/fonts.py или scripts/extract_brand.py. Обычная сборка не требует Python/LFS-оригиналов. Не изменяйте исходники брендбука ради рефакторинга.

## Изменения публичного контракта

Новый элемент требует схемы, renderer, CSS-состояний, примера и описания lifecycle. Композиции определяют семантические слоты, сетку и ограничения; проверяйте смену оформления без потери IDs, действий и содержимого. Изменение DOM/CSS проверяется потребителями и Constructor через опубликованный пакет. Не подключайте его checkout к библиотеке.

Обновляйте RU/EN вместе. В PR указывайте проблему, итоговое поведение, совместимость и доказательства; для визуальных изменений нужны сравнения, для схем — старые документы и отрицательные сценарии. Секреты, артефакты и локальные проекты не коммитятся. [Политика выпусков](operations.md).
