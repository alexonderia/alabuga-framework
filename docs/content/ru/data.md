# Форматы, ресурсы и экспорт

## Совместимость документов

validateDocument принимает схемы 1–5; правила нормализации описаны ниже. Неизвестная будущая схема отклоняется. Строгая схема означает, что новое сериализуемое поле требует оценки старых читателей; иногда нужна новая схема и явная миграция. SemVer npm-пакета не заменяет schemaVersion.

Переносимая оболочка alabuga-project, база alabuga-workspace, ревизии, корзина и AI-черновики принадлежат Constructor. Библиотека работает с AFDocument и не открывает IndexedDB. [Совместимость проектов приложения]({{CONSTRUCTOR_URL}}/docs/ru/data.html).

## Разрешение материалов

assetsBaseUrl задаётся на операцию renderer, fit или export и имеет приоритет. ESM по умолчанию использует ресурсы пакета, внешний IIFE — базу относительно URL script. Сборщик приложения должен опубликовать экспортируемые assets и передать подходящую базу. Совместимые пути ../assets/brand/... распознаются как встроенные материалы. HTTP(S), data URL и пользовательские относительные изображения сохраняют прежнюю семантику.

asset:<sha256> обслуживает callback потребителя. В renderer/fit он синхронно возвращает URL; в export resolveAsset асинхронно возвращает данные изображения. Отсутствующий материал при экспорте вызывает явную ошибку. Встроенные и локальные изображения подготавливаются до включения в HTML; внешние HTTP(S) остаются сетевыми.

## Автономный HTML

```ts
import {exportHTML} from '@alabuga/framework/export';
const html = await exportHTML(documentData, {
  runtime: {css: standaloneCss, script: standaloneScript},
  assetsBaseUrl: '/assets/',
  resolveAsset: async id => loadImageDataUrl(id)
});
```

CSS/script передаются явно и должны соответствовать установленной версии. Полный CSS содержит шрифты как data URL. HTML не требует редактора, Ollama или npm-реестра. JSON проекта сохраняйте отдельно для дальнейшего редактирования; HTML — готовый результат. PDF создаётся печатью браузера с включёнными фонами.

## Размеры адаптивных блоков

Framework 1.2 добавляет `widget.responsive`: `{tablet:{width:73,minHeight:320},mobile:{width:100,minHeight:240}}`. Ширина — целое число 1–100 процентов доступной строки с учётом промежутков, минимальная высота — 0–3200 CSS px. Поля независимы; отсутствующие значения сохраняют автоматическое поведение. Высота растёт с содержимым. Параметры действуют только на потоковые секции сайта: планшет 640–1023 px, телефон до 639 px по ширине контейнера документа. Базовая сетка и слайды сохраняются. Порядок задают прежние tabletOrder/mobileOrder; DOM и визуальный порядок совпадают.

Документы с responsive нормализуются в schemaVersion 4; явно заданная версия 4 сохраняется. Документы без новых полей версий 1–3 по-прежнему нормализуются в 3. Старые читатели Framework 1.1 отклоняют версию 4: для повторного открытия нужен Framework 1.2 или новее. Переносимая оболочка Constructor остаётся версии 3 — это отдельный формат.

## Подпись и номер слайда

Framework 1.3 добавляет page.chrome: header: {visible, text} и number: {visible, value, format, position}. Пустые text/value используют название проекта и порядковый номер. Форматы номера: padded (01), plain (1), total (1 / 10); положение: left, center, right внизу. Настройки действуют на текущий слайд, сохраняются при смене шаблона, подборе и экспорте. Подпись сохраняет единые отступы и размер 24 px на холсте 1600×900 независимо от оформления и размещения фона. Скрытая подпись сохраняет место, чтобы содержимое не сдвигалось.

Документы с chrome нормализуются в schemaVersion 5; явная версия 5 сохраняется. Для их открытия нужен Framework 1.3 или новее; документы без chrome сохраняют прежние версии 3/4.

Framework 1.3.1 добавляет независимые number.background (transparent, white, ink, blue, light) и number.color (inherit, ink, blue, white, muted). Без этих полей фон прозрачен, а цвет текста берётся из темы. Непрозрачный фон имеет отступ 2×8 px. Эти поля сохраняются в схеме 5 и требуют читателя Framework 1.3.1 или новее.
