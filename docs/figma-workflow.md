# Локальные источники Figma

Для проекта действует один сбор исходников, затем работа по сохранённым материалам.
Каждая правка компонента использует локальный архив. Новая сессия, другой компонент
или возраст снимка не служат поводом повторно обращаться к Figma.

Рабочая копия: [Design System](https://www.figma.com/design/ObAoKiDwraibmQrxUNvGWI/Design-System?node-id=0-1).
Начальная точка для реализации — [указатель архива](../design/figma/README.md),
для автоматизации — [manifest.json](../design/figma/manifest.json).
Этот порядок также записан в [AGENTS.md](../AGENTS.md).

## Что входит в единовременный сбор

| Материал | Что сохранять |
| --- | --- |
| Проект | File key, страницы, секции, иерархию узлов, дату получения |
| Компоненты | Все семейства и варианты, свойства, размеры, auto-layout, отступы, состояния |
| Основа | Переменные со значениями по режимам, привязки, текстовые стили, шрифты |
| Визуальный эталон | Общий снимок секции и читаемые снимки семейств со всеми состояниями; отдельные детали при необходимости |
| Ресурсы | Исходные SVG/изображения локальными файлами с node ID, размерами и контрольными суммами |
| Контекст | Подробные данные компонентов, которые нельзя восстановить из общей иерархии |
| Учёт | Индекс покрытия и явный список отсутствующих материалов, без подмены эталонов снимками реализации |

Сначала составьте общую инвентаризацию. Считайте данные одним пакетом для всего
проекта, загрузите ресурсы до истечения временных ссылок и запишите материалы
в `design/figma/snapshot-<дата>/`. Не запрашивайте один и тот же узел повторно
ради другого представления уже полученных данных. Достаточность определяется
покрытием вариантов и состояний, а не только числом вызовов инструментов.

Манифест связывает исходные файлы с компонентами и фиксирует дату, способ сбора,
размер и SHA-256. Извлечённые правила и решения веб-реализации хранятся отдельно
в `design/*-rules.json` и `design/*-assets.json`; неизменённые SVG — в `src/icons/`.
Брендовые PDF остаются в `docs/brand-sources/`. Временные URL ресурсов не являются
источником для будущих задач или зависимостью во время выполнения.

## Как выполнять дальнейшие правки

1. Найдите семейство в `manifest.json`: общая metadata, подробные данные,
   скриншоты и компонентные правила перечислены раздельно.
2. Используйте сохранённый эталон, локальные SVG и PDF. Приложенный пользователем
   скриншот также подходит; запишите его происхождение и доступность на диске.
3. Сравните реализацию с этим эталоном. Браузерные снимки и отчёты проверки
   сохраняйте в `artifacts/` или `test-results/`, отдельно от исходников дизайна.
4. Дополните правила компонента, если приняли решение для веба: например,
   реальная длина месяца, читаемый контраст, высота строки без обрезки текста.
5. Выполните `npm run check:design` и необходимые проверки реализации.

## Пробелы и обновление

Первый архив восстановлен из уже полученных материалов 21–22 октября 2026.
Общая инвентаризация и переменные сохранены; подробные контексты и снимки покрывают
только часть проекта. Манифест содержит точный охват каждого семейства.
Для Calendar использован скриншот пользователя: оригинального файла приложения
в репозитории пока нет, и снимок реализации не подставляется вместо него.

При пробеле проверьте соседние компоненты, локальные PDF и приложения пользователя.
Если этого недостаточно и Figma доступна, получите недостающий материал один раз
и сразу добавьте его в архив, индекс и список контрольных сумм. При ошибке доступа
или квоте отметьте пробел и продолжайте по имеющимся источникам там, где это возможно;
повторные попытки одного запроса в каждой задаче не нужны.

Полное перечитывание проекта допустимо по явному запросу пользователя на обновление
макета. Сохраните новую версию отдельным пакетом, укажите изменившиеся узлы и сделайте
её текущей в манифесте. Предыдущий пакет сохраняется для воспроизводимого сравнения.
