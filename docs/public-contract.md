# Public compatibility contract

Calendar navigation preserves the existing widget date field, two-argument renderCalendar call, CSS classes and data-date/data-prev/data-next hooks. Arrow keys, Home/End and Page Up/Down (Shift for years) move focus without changing the value; Enter/Space/click select. Short months clamp to their last day and navigation remains within schema years 0000–9999. One day has tabindex=0. Header controls and the live month heading remain mounted; same-month selection preserves day buttons. Selection updates DOM/focus before calling onSelect; renderDocument updates its data before dispatching af:change, so hosts can synchronously update or destroy safely.

renderCalendar is also exported from the root/standalone Alabuga object. Its optional third argument adds confirm/onCancel, initial value and inclusive min/max bounds; mode:'range' uses a typed {start,end} value and callback. Options initialize state. Confirm buffers changes; Cancel/Escape restore the last committed value before onCancel. Empty single confirmation accepts the focused date; incomplete/out-of-bounds ranges cannot confirm. Reverse ranges are ordered, callbacks receive copies and navigation never emits. The returned HTMLElement owns internal listeners only and is released by removal. These options are not AFDocument schema fields: its widget retains immediate single-date behavior. Component geometry follows the user-supplied screenshot (250 px, 32 px days, five-week heights 260/304 px); reference provenance, contrast adjustments and real-date correction are recorded in design/calendar-rules.json. Calendar widget DOM hooks remain intact while its redundant outer frame is removed.

initComponents enhances input.af-datepicker[type=date] without changing its signature or standalone JS/CSS delivery. The original input retains name/value/defaultValue, required/min/max, native input/change, FormData and host custom validation. A nameless text proxy displays DD.MM.YYYY; its original value remains ISO. Invalid/incomplete typed dates clear the stale value and invalidate the original; supported years are 0001–9999. Browsers without native date support receive equivalent format/boundary validation. The existing Calendar provides a native modal dialog popup, draft/confirm/cancel, keyboard focus return and bounded days. readonly/disabled/fieldset/reset and external value changes dispatched as input/change synchronize; cleanup restores native markup and releases listeners/dialog. data-af-date-native opts out. Generated proxies are excluded from Framework form validation, which follows willValidate. DatePicker is an HTML component and adds no serialized AFDocument properties or public JS entry point. Source nodes and assets are recorded in design/datepicker-rules.json.

DatePicker follows standard Field sizes: af-input--sm = 32 px / 12 px text / 16 px icons, no modifier = 40 / 14 / 20, af-input--lg = 48 / 16 / 24. Class changes synchronize without recreating the control or losing a calendar draft. S/M are user-requested extensions of the saved L-only source. Calendar popup dimensions stay unchanged.

Option-btn and Multi-switch are CSS styling for native checkbox/radio inputs, preserving checked, native keyboard grouping, validation, FormData, disabled fieldsets and reset. af-chip adds 16/20/24 px labels; af-alert supports 32/40/48 px minimum single-line sizes and grows for wrapped content. Error/danger aliases are supported. Existing af-badge remains unchanged. initComponents delegates data-af-dismiss for alerts and chips and moves focus to the next/previous dismiss button in the same parent when available. Cleanup releases delegation. af-dialog--compact adds named slots and 350 px / 16 px geometry to existing native dialogs. Breadcrumbs and aria-current links are CSS-only navigation markup. These components add no AFDocument fields, JS initializer or runtime dependency. Visible P2 variants were rechecked against the three user-supplied screenshots and saved properties. Default Chip/Alert colors and Link states now follow the source. Opt-in af-chip--accessible, af-alert--accessible and af-link--accessible retain darker text; af-link--inline supplies blue underlined inline links. Detailed property/image export coverage remains partial and is recorded in design/secondary-components-rules.json.

Document renderer callouts explicitly use af-alert--accessible and text links use af-link--inline, preserving readable document content while source-palette components remain available. Existing base classes, text nodes and DOM authoring hooks are retained.

Named af-icon modifiers provide source-based CSS glyphs in 16/20/24 px. Named icons default to M=20 px; bare af-icon remains the legacy 24 px wrapper. Nested custom SVG root sizes are unchanged. Buttons own af-btn__icon.af-icon geometry, including the Secondary Round L 20 px exception. Original two-color loaders retain reduced-motion handling. SVGs are embedded into existing CSS outputs; no new entry point, JS initializer or schema field. Available original assets and explicit scaled-size extensions are recorded in design/icon-catalog.json.

Framework uses independent SemVer. Document schema versions 1, 2 and 3 are read and normalized to 3. This format number is independent of the npm package version. All explicit exports in package.json are supported; `/src` and `/dist` imports are private. JS uses ESM; standalone.js exposes Alabuga. CSS must be imported explicitly.

Stable runtime API: validateDocument, renderDocument, initComponents, composition factories, layout variants, fitting and export. DocumentController supports update, synchronize (authoring mode), destroy, getDocument, slide navigation and overflow checks. Invalid updates are atomic. destroy is idempotent; remount releases the prior controller. initComponents returns cleanup.

Named surfaces extend af-card through CSS only. af-card--outer and af-card--inner retain 32/16 px padding/radius on desktop and mobile, with a 16 px vertical gap and direct text margins reset. Filled, outline (2 px), outline-thick (3 px) and elevated (0 2px 3px 0 neutral/300) appearances are separate emphasis choices. White nested cards reset to primary text; controls keep their own styles and inverse CTAs are explicit. Forced colors provide a system border for fill/elevation. Legacy af-card without geometry modifiers keeps its prior block layout, neutral border and 20 px mobile geometry. Existing af-surface--plain/card renderer flags, document fields and DOM hooks are unchanged. Source values and implementation decisions are recorded in design/surface-rules.json; the inspected Figma file has no separate Card component family.

initComponents enhances existing single select.af-select controls with Select/List/ListItem UI. It retains the original form control and its value/events; cleanup restores native markup. Size modifiers are af-select--sm and af-select--lg. data-af-readonly and aria-readonly prevent user changes; data-af-select-native, multiple and size>1 retain native rendering. JS and CSS distribution and the initComponents signature are unchanged; select assets are embedded in CSS. The generated control/list DOM is owned by Framework and must be cleaned up before the host removes it.

Resource options are per operation. assetsBaseUrl overrides the package base. Built-in legacy `../assets/brand/...` references are recognized; user-relative paths retain browser semantics. asset:<sha256> uses the caller's resolver. Framework never reads storage. Export receives runtime CSS/script and an optional async resolver. Missing exported assets fail explicitly. External HTTP(S) images remain network resources.

Button appearances retain independent selected/pressed/loading/disabled states. aria-busy visually hides the existing label while preserving accessible naming and width; native buttons should also use disabled. initComponents blocks click/auxclick activation of .af-btn[aria-busy=true] and .af-btn[aria-disabled=true]; cleanup releases this behavior. af-btn--inverse explicitly styles dark-surface CTAs. Composition selectors do not override all nested button sizes or colors; fitted slide typography remains separate.

af-btn--icon adds fixed S/M/L squares (32/40/48 px) with existing size/appearance/state modifiers; af-btn--round makes those icon buttons circular. af-btn__icon is a 16/20/24 px slot, with the source exception of 20 px for Secondary Round L. SVG dimensions are owned by the supplied asset. Icon-only actions need an accessible name on the native button or anchor. af-btn__icon--placeholder reproduces the optional Figma square placeholder. No new JavaScript API is introduced.

af-btn__icon--info supplies an actual information symbol using existing size-specific Figma SVGs embedded in CSS; its mask uses the asset's intrinsic size and the button's current text color, including forced colors. The demo uses this icon for the action "More information". af-dropcap, af-divider and af-divider--ornament are optional legacy Framework styles without a confirmed source in the reviewed design materials; documentation identifies them as extensions, while existing selectors and document behavior remain supported.

Direct af-btn__icon children of icon-only buttons and their loading pseudo-element use the same 50% anchor and negative half-size translate. SVG geometry stays unchanged; loader rotation uses its independent transform. Documentation presents each list kind in a separate example block, preserving earlier links to the basic list and extension examples.

Component typography adds af-title--md, af-body with --md/--sm/--xs/--xxs and af-label--lg/--sm/--xs; modifiers accompany their base classes. Default af-body is L (16 px), af-title is L (22 px) and af-label is M (14 px). Heading tracking is zero. Generic Display stays 44 px; the existing 36 px mobile exception is scoped to page documents. Field label sizing and fitted slide typography retain their separate context rules. DOM authoring hooks are unchanged.

ul.af-list uses original 33 px diamond/outline/triangle markers in CSS and left alignment. af-list--outline and af-list--triangle select alternate markers. af-bullet with matching --outline/--triangle modifiers provides the standalone 33 px decorative marker. Supply role=list for styled unordered lists so WebKit retains list semantics; the document renderer adds it automatically. Ordered af-list retains native start/value numbering. List children remain the original li nodes in content order; no wrappers or serialized fields are added.

af-checkbox and af-radio remain native input elements and work with CSS alone. Their --sm/--lg modifiers select 16/24 px icons (default 20 px). af-check sizes label typography from its direct input. Native checked, disabled (including fieldset), indeterminate, required, FormData, reset and keyboard behavior remain intact; forced-colors mode uses native rendering. Assets remain embedded in the existing CSS output.

af-switch remains a native checkbox with role=switch and the single Figma L size (44×24 px). Input --sm/--lg modifiers size both native controls and their af-input-wrap, including related field labels/helpers and icon slots. Wrapper states follow the input through CSS; disabled fieldsets are supported. af-input-hint uses embedded, size-specific info/error/success SVGs. af-textarea--success adds the existing success pattern to textarea without changing serialized documents.

initComponents updates existing [data-af-counter-for] text nodes from native input/textarea values and maxlength. Counters follow native UTF-16 length, input/change, maxlength mutations and uncanceled form resets. Applications dispatch input/change after programmatic value updates. Cleanup releases listeners/observers and keeps the last displayed count. Native controls are not replaced; there are no new public JS entry points or runtime dependencies.

Public DOM authoring hooks: `[data-section-id]`, `[data-widget-id]`, `[data-action-id]`, `.af-page`, `.af-slide`, `.af-panel`, `.af-widget`, `.af-widget__title`, `.af-widget__content`, `.af-prose`, `.af-heading`, `.af-slide__title`, `.af-section-background`, `.af-table-scroll`, `.af-title`, `.af-label`, `.af-caption`, `.af-metric__value`, `.af-quote__text`, `.af-quote__author`, `.af-feature`, `.af-feature__title`, `.af-feature__text`. Prose children follow document content order; list items, gallery figcaptions, table body rows/cells and cards follow their data order. Constructor's framework-adapter owns its use of these hooks. Structure/selector changes that break editing require a major release.

CSS component classes, documented modifier classes, ARIA/data state attributes and existing --af-* tokens remain compatible within a major. Core, semantic and component token layers preserve the previous effective values, including accessibility adjustments. design/figma-tokens.json is the original design snapshot; design/token-layers.json records the effective CSS mapping and explicit accessibility adjustments. `npm run tokens` deterministically generates layers; `check:tokens` detects drift and missing references.

Patch fixes preserve contracts. Minor versions add compatible APIs. New serialized properties must be checked against older strict validators; use a new document format and migration when necessary. Breaking changes require a new major and migration guide. Previous major critical fixes are supported for six months. Published archives are immutable.

ResponsiveSize and Widget.responsive are public schema additions in 1.2.0. Tablet/mobile width (1–100 percent) and minHeight (0–3200 CSS px) affect only flow page sections at container breakpoints 640/1024. Missing fields retain legacy sizing. New overrides promote documents to schemaVersion 4; schemas 1–3 without overrides still normalize to 3, explicit 4 stays 4. Old readers reject 4. Content expands beyond minimum height; no text is clipped by a requested height. Export embeds the matching runtime/CSS and preserves the overrides.

## Slide annotations (1.3)

`Section.chrome` / `SlideChrome` supports optional header visibility/text and number visibility/value/format/position. Chrome documents normalize to schema 5; legacy normalization is unchanged. Header geometry is independent of theme, fitted state and background placement. `.af-eyebrow` reserves space when hidden; `.af-slide__number` is omitted when hidden. `renderDocument` accepts optional `slideOffset` and `slideCount` for isolated thumbnail numbering. The same serialized annotations are used by ESM, IIFE, preview and HTML/PDF export.

Framework 1.3.1: optional SlideChrome.number.background and .color use documented brand palette enums. Defaults remain transparent/themed; solid backgrounds add 2×8 px padding. data-number-background and data-number-color on .af-slide__number carry the selected variants in ESM and standalone output. Colors persist through fitting, project storage and export.
