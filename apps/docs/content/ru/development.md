# Разработка

## Чистая установка

Клонируйте приватный репозиторий, установите версии Node/npm из конфигурации и выполните `npm ci`. Изменение зависимостей оформляется вместе с корневым package-lock.json. Не создавайте отдельные lock-файлы в пакетах. `npm run dev` собирает автономный runtime и запускает Vite. Для воспроизведения отчётов Python нужен отдельно; обычная сборка приложения его не требует.

## Команды

Модульные проверки отдельной части: `npm test -w @alabuga/framework`, `npm test -w @alabuga/ai`, `npm test -w @alabuga/editor`, `npm test -w @alabuga/ai-server`. После `npm run build:docs` команда `npm test -w @alabuga/docs` проверяет документацию отдельно; полная `npm run check:docs` дополнительно проверяет ссылки между приложениями. `npm run test:release` проверяет собранное приложение без Ollama и сохраняет автономные примеры, PDF и снимки. Необязательные сценарии обработки материалов используют `python -m pip install -r scripts/requirements-assets.txt`; готовые WOFF2 уже включены в репозиторий.

| Команда | Результат |
| --- | --- |
| `npm run typecheck` | Типы пакетов, приложений, сценариев и тестов |
| `npm run check:boundaries` | Запрещённые импорты между пакетами |
| `npm run build:framework` | Библиотека и автономный runtime |
| `npm run build:ai` | Пакет генерации |
| `npm run build:editor` | Редактор и демонстрация |
| `npm run build:docs` | Справочник и руководства RU/EN |
| `npm run build:server` | Исполняемые файлы API и инициализации |
| `npm run build` | Полный выпуск в dist/site |
| `npm test` / `npm run test:ai` | Модульные проверки |
| `npm run test:browser` | Три браузера, отдельный тестовый сервер |

Сборка редактора и документации автоматически готовит библиотеку. Они не скачивают и не запускают модель. После изменения библиотеки пересоберите runtime, используемый автономным экспортом. Полная сборка всегда выполняет этот шаг.

## Новый элемент или композиция

Опишите элемент в схеме и общем renderer, затем добавьте настройки редактора и пример в документации. Для композиции задайте семантические места, допустимые компоненты, варианты сетки и ограничения текста. Проверяйте сохранение идентификаторов, смену компоновки, экспорт и мобильный порядок. API не должен зависеть от внутренних файлов редактора.

Новый провайдер реализует AIProvider. Он возвращает данные по переданной схеме и уважает AbortSignal. Отдельно проверяются неверный JSON, таймаут, отмена и недоступность сервиса. Измерение и оформление остаются кодом конструктора.

## Работа через PR

Одна задача — одна небольшая ветка. В PR укажите проблему, итоговое поведение, совместимость и результаты проверок. Для визуального изменения приложите снимки; для схемы — тест старого документа; для API — отрицательные сценарии. Изменение общей библиотеки требует проверки потребителей. Документация обновляется сразу на RU и EN.

Изменения веток не должны включать модели, локальные проекты, секреты и полный каталог тестовых артефактов. Владельцы областей назначаются командой после создания репозитория; до этого конкретные GitHub-пользователи не выдумываются.
